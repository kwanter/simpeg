# Git & Version Control Preferences

- Prefers deleting branches after their PRs are merged (both local and remote), rather than keeping them for reference — wants the repo left with only `main` and no stale refs. Confidence: 0.7
- Requires explicit user instruction before staging/committing: execution proceeds through RED → GREEN → VERIFY with commits withheld, and the user then authorizes the commits — typically inside the same terse message that also orders the next phase (e.g. "commit fase 2 dan 3 sekaligus kemudian lanjut ke fase 3"), so authorization and the next instruction arrive together. Confidence: 0.65
- Makes one atomic commit per ticket/unit of work, scoped to a single file when that matches the unit (e.g. each contract-pin test file committed separately). Confidence: 0.6
- Writes conventional-commit subjects with a scope (`test(izin): pin the …`) and commit bodies that record the verification evidence — what was pinned, the temporary mutation used to prove the pin bites, and an explicit statement that production code is unchanged. Confidence: 0.55
- Appends a `Co-authored-by: CommandCodeBot <noreply@commandcode.ai>` trailer to commits. Confidence: 0.55
- Commit messages state explicitly when recorded files were not authored or altered by this session (committed exactly as they already existed on disk), so the commit does not claim authorship of others' work. Confidence: 0.5
- Scopes a commit deliberately at both ends: adds a file beyond those the ticket names when the ticket's purpose requires it (e.g. tracking the plan that governs the work, because an untracked plan cannot be reviewed or reverted alongside it) with the justification written into the commit body, and explicitly excludes files that were untracked before this work as a separate decision. Confidence: 0.5
- Reads "commit X dan Y sekaligus" as "both now, in this turn" rather than "one commit": still issues one commit per coherent change set, splitting a docs/spec change from a test change, because squashing them would make reverting one phase withdraw the other. Confidence: 0.55
- When a plan's process rule cannot honestly be honored (e.g. one atomic commit per ticket is impossible because two tickets' hunks interleave in the same files), merges them into one commit rather than hand-crafting patches, and records the deviation, the violated rule's ID, and the rationale in the commit body instead of staying silent. Confidence: 0.55
