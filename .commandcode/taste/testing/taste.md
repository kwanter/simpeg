# Testing Preferences

- For tests that count database queries against a table, scope measurement to the method invocation under test and exclude setup SQL; count every SQL statement that references the table, including indirect references through joins, subqueries, or CTEs, rather than only direct reads/writes. Confidence: 0.7

- When the same contract applies independently to multiple methods, prefers separate tests for each method so a failure identifies which method violated the contract. Confidence: 0.65

- Requires tests to be deterministic: when a factory randomizes an attribute that drives assertions (e.g. `IzinFactory` randomizing `jenis_izin` across single-level and two-level types), pin it explicitly to a known value rather than relying on the randomness. Confidence: 0.7
- Treats intermittent/flaky test failures as real defects to reproduce and root-cause, not to dismiss as noise — reproduces them (in isolation and via repeated runs) before concluding, and distinguishes "test defect" from "application bug". Confidence: 0.7
- Confirms a determinism/flakiness fix by running the affected test class and the full suite repeatedly (e.g. ~20x the class, ~4x the full suite) before declaring success. Confidence: 0.65
- Removes temporary debugging instrumentation (dump/dd/fwrite diagnostics) before finishing and keeps production source untouched (verified via a clean `git status` on source directories). Confidence: 0.7
- Treats the existing characterization suite as the regression oracle in a refactor: those test files must not be modified, skipped, weakened, or have assertions removed. Confidence: 0.7
- Re-verifies quantitative claims (test counts, assertion counts) by running commands and counting per file rather than copying numbers from earlier artifacts. Confidence: 0.65
- Places each acceptance criterion at the seam where the behavior is actually reachable, so the test can genuinely go Red first — e.g. moving an assertion from the HTTP seam to a service seam when request-level validation makes the HTTP path unreachable. Confidence: 0.6
- Proves contract-pin tests are not vacuous with a mandatory temporary mutation: when a test pins already-correct behavior (so it passes immediately rather than honestly Red), temporarily mutate the production line to confirm the test fails, then restore it exactly and verify the source tree is clean (`git diff app/` empty). Confidence: 0.65
- Prefers reflection-based structural assertions over grepping raw source text — e.g. using `ReflectionMethod::getFileName()` (which returns the trait's file for an inherited method, the class's file for a local one) or `ReflectionClass::getTraitNames()` to prove a method is no longer declared locally — because text pins break on harmless reformatting; when a textual check is kept at all, scopes it to the relevant method body rather than the whole file, since a whole-file symbol grep flips on comments, renames, or reformatting and its file-level scan also conflicts with the project's own architecture-map guidance. Confidence: 0.6
- Extends structural assertions to cover deliberately retained branches (e.g. a defensive guard string), proving they bite by temporarily deleting the guarded line and confirming the test fails. Confidence: 0.5
- When a plan's structural assertion cannot honestly pass within a single ticket's scope (the targeted logic is only fully removed by a later ticket), narrows the assertion to what that ticket can achieve — e.g. reflecting over one method body — and defers the whole-artifact assertion to the later ticket, surfacing the plan deviation to the user instead of writing a test that cannot go green. Confidence: 0.5
- Pins a new service's public API with reflection. When the contract is intentionally additive-compatible, asserts that every required method exists and is public without failing solely because extra public methods are added; use exact-set equality only when the API is intentionally closed. Confidence: 0.85
- Proves a branch is dead with a dedicated equivalence test before deleting it: enumerates the full input combination space (e.g. 6 actors × verification statuses × null/non-null letter) and pins both the total combinations checked and the number of permitted outcomes as tripwires, so any later shift in the authority's decision forces the equivalence to be re-proven before the deletion stays valid. Confidence: 0.55
- Tightens upper-bound-only assertions to exact equality (e.g. replacing `assertLessThanOrEqual(1, $x)` with `assertSame(1, $x)`), because an upper bound passes vacuously when the collector silently matches nothing; confirms the tightened assertion still passes so the collector is proven to match, and escalates the severity of such findings because a flagship criterion whose assertion cannot go Red is unprotected. Confidence: 0.65
- Verifies "row unchanged" claims by comparing the raw stored row (`DB::table(...)->first($cols)`) rather than a hydrated model, since date casts return `Carbon` objects and `assertSame` on arrays compares object identity; when such an assertion fails, the first move is to fix the method by strengthening it, not to weaken the assertion. Confidence: 0.55
- Pins a memoization/caching contract through observable behavior rather than call counts: mutate the input so a fresh evaluation would flip the result, then assert the second call still returns the first answer. Confidence: 0.55
- When an accessor must reuse a memoized model resolution, requires identity-level verification of the exact same PHP object (e.g. `assertSame()`), not merely equality of its record identifier; test missing-record/404 behavior separately. Confidence: 0.8
- Keeps test names aligned with what is asserted, renaming when an assertion is tightened (e.g. `…_at_most_once` → `…_exactly_once`) instead of leaving a name that understates the contract. Confidence: 0.5
- Refuses to relax an exact-contract assertion to satisfy a reviewer's complaint that the failure message is unhelpful: instead of downgrading `assertSame`/exact-set comparison to a containment check (which would release the pinned criterion), strengthens the failure message to say the acceptance criterion must be amended first — never delete an assertion just to make an addition pass. Confidence: 0.55
- Declines to add new assertions for behavior already pinned by the inherited characterization suite, treating duplicate coverage as added cost with no new coverage, and spends the effort on the structural gap the ticket actually targets. Confidence: 0.55
- When a value-only assertion cannot be made fully deterministic, does not pretend otherwise: minimizes the false-positive window and documents the probability math and the residual risk in a comment (including why the suggested fully-deterministic remedy is impossible, e.g. both UUID generators read the same `$uuidFactory` hook). Confidence: 0.55
- Runs a zero-suppression audit as part of every phase's verification gate: greps `app/` and `tests/` for suppression and skip markers (`@phpstan-ignore`, `@psalm-suppress`, `eslint-disable`, `markTestSkipped`, `->skip(`) and expects zero matches, so a warning is fixed rather than silenced. Confidence: 0.5
- Consolidates several narrow tests into one superset test (e.g. per-action `store`/`update` scans into a single all-methods scan), accepting a drop in test count when assertion count and coverage grow and every consolidated assertion is proven to bite by mutation. Confidence: 0.5
